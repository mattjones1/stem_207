# Activities and labs: the content model

How an activity record is shaped, how labs are built, and the rules that keep every activity complete. Read before adding or editing an activity, a lab, standards, or Go deeper links.

## Coding activities (Coding 2.0, planning/CODING_PLAN.md)
- Every coding activity also has (the linter requires them):
  - `primm: { predict, investigate: [2–3], modify, make }`: shown as **Think like a coder** before the steps (Run is a fixed line).
  - `career: { role, industry, what }`: shown as **Who does this in Maine**. Roles and industries only; **never name a company** without permission.
  - `explain`: the **Explain your build** prompt, an optional box in the debrief saved as `explain` on `mission_completed`. Me lists these as **My portfolio**.
  - `group`: one of `STEM.codingGroups` (`areas.js`). The Coding page shows activities by group; a group with no activities is hidden (Web development until it has reviewed content). An activity from another category joins with `alsoIn: ["coding"]` plus a `group` (the Snowplow lab and Sense–Think–Act are in robotics).

## The harbor engine (shared by every lobster-boat lab)
- **`assets/js/labs/harbor-engine.js`** (`SE.harbor`, loaded before `minipy.js`): the block catalog (`BLOCKS`), `make`, `clone`, `countBlocks`, `parse` (starter shorthand), `parseGrid`, `isWall`, and the interpreter `run(list, st, ctx)`, a generator that yields once per block so labs can step through. Bounded: 400 operations, call depth 5, and a no-progress check on `untilGoal`; never `eval`.
  - Map squares: `#` ledge, `.` water, `S` start, `G` wharf/mooring, `*` trap buoy, `o` dashed spot, `x` search mark (Captain Code).
  - Captain Code additions, unused by Harbor Code: the side sensors `ifLedgeLeft` / `ifLedgeRight` (with else), search marks (`st.visited`), call counting (`st.calls`), `startState(g, dir)`, `check(L, st, g) → { ok, reason, values }`, `sail(L, grid, main, fn)` (a whole run, for tests and "Test all channels"), `validateGrid(rows)`, and `visibleFrom(g, x, y, r)` (fog).
- **`assets/js/labs/harbor-editor.js`** (`SE.harbor.editor(box, opts)`): the tap-to-add block editor (toolbox, your-block box, program, Python view). Harbor Code calls it with its old options, so its markup is unchanged; Captain Code adds `undo` (Undo/Redo, Ctrl+Z / Ctrl+Y), `countFn`, labels, and the variable name.
- Harbor Code (`lab-coding.js`, id `rover`) keeps its levels and its own run loop. `tests/labs/test_harbor_code.py` compares its editor markup with `tests/fixtures/harbor-code-dom.json` (record again with `--record` only for an intended change).

## Captain Code (the flagship coding workshop)
- **Instructor guide:** `missions/coding/captain-code/` (README, `01-instructor-guide.md`, `02-printable-cards.md`; the same template for all three workshops). When a level, stage, budget, or dataset result changes, update the guide's course map and answer guide too.
- Lab `captain-code` (`lab-captain.js`, `.cc-` styles), levels in `captain-levels.js` (`SE.captainLevels`): Casco Bay 10 (the 90-minute workshop), Penobscot Bay 12, Down East 12, as `chapters`. Library entry `lab-captain-code` (`featured: true`, listed before Harbor Code); template `tpl-ws-captain-code` (`reviewed: false`).
- A level: `id, title, concept, briefing, goal, steps?, hints: [notice, idea, scaffold], learned, grids: [map…], worlds?, dir, blocks, fog?, needGems?, needDrops?, carry?, minCalls?, fnName?, varName?, budget?, par?, stretch?, predict?, plan?, design?, legs?, lesson?, starter? (Python), reference (Python), wrong: [{ src, reason }]`.
- **Lessons (learn first, then try):** `lesson: { title, cards }` (set in `captain-levels.js` from `LESSONS`) shows in place of the workspace the first time a level opens (`stem207.captain.lesson.<levelId>.<userId>`), and **Lesson** in the brief reopens it. A card has `h` and `say`, plus `show` (block lines; two spaces = inside), `example` (`{ grid, dir, src, fnName?, varName?, tip }`: a tiny real chart stepped with the engine, showing lap counts and if answers), or `check` (`{ q, options: [[answer, right, why]] }`: the right answer unlocks Next; every answer explains itself; nothing is scored). Lessons: cb-5 Repeat, cb-6 if / else, cb-7 an if inside an if, cb-8 variables, cb-9 your own block, cb-10 the captain's routine, de-5 nested loops, plus recaps (pb-7, de-6, pb-9, de-8, pb-10, de-10). Logs `lab_lesson_viewed` and `lab_lesson_check` (ids and right/wrong only).
- **Block count:** every block counts once, nested ones too, plus the blocks inside the student's own block; a call is 1. A route over `budget` still runs, then the feedback asks for a loop, a variable, or their own block; it doesn't win. Any program that meets the objectives passes.
- Mechanics, all checked against the real run: predict first (`predict`: tap a square before the first run), plot your course (`plan`: the run marks where the boat left the plan), fog (`fog: 1`: only the 3×3 around the boat is drawn, and the chart's label doesn't reveal hidden squares; sensors still read the true map), channels (two or more `grids` must all pass with one program), and the chart designer on level 10 (`design`: validated with `validateGrid` and the Level Designer's `route`).
- **Plot your course** (every level but fog; open first where `plan`): tap squares in order for the route, then tap a trap buoy or dashed circle on the route to plan the job there (H or S on the chart). Arrows show the heading on each square, and **My plan in words** lists it from the boat's starting direction ("Forward 2 · Turn right · Haul trap"), with Listen. It's a plan in words, never blocks. A run marks the first square where the boat left the route, or a planned job it didn't do.
- **Guess where it stops** is on every level but fog. It's required before the first run only where `predict`; elsewhere it's optional and earns no mark.
- **Loops** (the editor's `loops` option and the engine's `ctx.loopTicks`): containers end with an "end repeat" / "end if" foot and the gap below says "after the loop"; tap a count to pick 1–12; **See it unrolled** lists what a Repeat stands for; a running loop shows "lap 2 of 4" on the block and `i = 1` on its Python line; **Select blocks** → **Put in a Repeat** wraps blocks that sit next to each other (Undo covers it). Ifs report their answer (`answer`) so the status line says yes or no.
- **Level 10** (`legs`): traps A–D carry letters on the chart and tick off in the readout in any order; a failed run names the legs that worked and where the bug is. Part 2, **Design my chart**, opens after Part 1 is won (or for a student who finished the level before): four numbered steps (boat, mooring, 2–4 traps, ledges) and a live **Sailable!** check.
- Marks on a win: **Made it**; **Par** (at or under `par`); **Compass** (a correct prediction, a `stretch.blocks` target, or no failed runs). None depends on time or attempt speed. Each mark says what it checked ("Compass: exact guess", "Compass: first run"), so a `stretch.text` without `blocks` must say "first run", and a `stretch.blocks` level needs a `stretchRef` program that meets it (both checked by `test_captain_levels.js`).
- **Screen (lean pass, November 2026):** the brief leads with the goal, then a quiet row of small links, **Listen**, **Hint**, and **Lesson** (`briefFirst`, `compactTools`; learn/why fold into "Why this level?"). The block counter carries the budget ("7 / 5 blocks · too many"), and a Par chip shows only where par ≠ budget. The program gets the whole left column and grows with the screen; **Python is on by default** under the chart (the **Python** chip hides it for the session, `stem207.captain.py`). Under the chart: Run / **Step (1 block)** / Reset (+ Test both); the status line counts steps ("Step 3: Forward"). Then the mode panel and **Captain's tools** (Plot your course, Guess where it stops, Python, Design my chart, Speed). After two failed runs, the feedback points to Hint. There's no Extra help, Bigger blocks, or educator Demo. The shell's optional `landing(el, { user })` shows the start screen; `level.briefing` shows the harbor master's line.
- Finishing a region shows a graduation panel and certificate; Casco Bay also earns the **Certified Captain** patch (`rule: "labRange"`). Level 10's win shows a printable **Voyage Card**, and its result saves the chart and Python.
- Tests: `node tests/tools/test_captain_levels.js` (every reference solution sails through the engine on every channel, within budget and equal to par; wrong programs fail for their reason; fog hides the mooring) and `python3 tests/labs/test_captain_code.py`.

## The web kit (shared by the two web labs)
- **`assets/js/labs/web-kit.js`** (`SE.webKit`, loaded before `lab-web.js`): the built-in pictures (`lighthouse.svg`, `lobster-boat.svg`, `muffins.svg`, `kayak.svg`, `tackle.svg`, as inline SVG), the preview document `srcdoc(code, { css, map, head })`, WCAG `contrast`, `summarize(doc)` (Web Builder's page reader), `textContrast(doc)` (every element with its own words against the nearest opaque background; `null` over a picture, gradient, or see-through color), `cssColors` / `setCssColor` / `toHex` (the color helper), and `tagSource` (Find it's map from preview elements to code).
- **Preview safety, in layers:** the iframe is `sandbox="allow-same-origin"` with no `allow-scripts` (so no scripts, forms, popups, or navigation; the parent can still read the rendered DOM); a CSP meta tag `default-src 'none'; img-src data:; style-src 'unsafe-inline'`; `sanitize()`, a DOM allowlist in an inert `DOMParser` document (drops scripts, frames, forms, media, SVG, `on*` attributes, and `javascript:`/`data:` links; unknown elements are unwrapped); then `defuse()`, which rewrites `src`, `srcset`, `url()`, and `@import`. Link clicks are caught in the parent and never followed. In Node (no `DOMParser`) the other layers still apply.
- Web Builder (`lab-web.js`) keeps its own levels, `RULES`, and iframe; `SE.webBuilder` exports are unchanged, and it still accepts only its two pictures.
- **More pictures** for students' own topics (moose, loon, puffin, fox, deer, a mountain trail, a tree, waves, a soccer ball, a basketball, a game controller, a guitar, a paintbrush, a robot, a rocket, a light bulb), all drawn SVG. `PICTURE_INFO[file] = [description, keywords]` gives alt-text suggestions and the words that point to each picture. `srcdoc(…, { title })` sets the page's `<title>`.

## The web studio (shared by Build Your First Website and the Website Builder)
- **`code-editor.js`** (`SE.codeEditor(textarea, { lang, shellTop, shellBottom })`): no dependency. It keeps the real `<textarea>` (typing, the browser's Undo, screen readers, and phone keyboards work as always; the text is drawn with `-webkit-text-fill-color: transparent` over an `aria-hidden` colored copy, so its real color still passes contrast checks). Line numbers; locked "shell" lines above and below (like `<!DOCTYPE html>` … `<body>`), each with a short "why"; auto-close on `>` (not void tags); auto-indent on Enter; Tab adds two spaces and **Esc, then Tab** leaves; the tag pair at the cursor is outlined; Ctrl+F searches. `goTo(start, end)` selects, scrolls, and flashes; `showInsertPoint(at, label)` draws a dashed "add it here" line and never edits the code; `tidy()` re-indents in one undoable edit. Pure helpers: `highlight`, `pairAt`, `tidyHtml`, `tidyCss`.
- **`web-studio.js`** (`SE.webStudio`), deterministic (no AI, no network): `explain(code, at, lang)` (**What does this do?** for tags, attributes even mid-word, the words inside an element, CSS selectors, properties, and values like hex colors and rem); `cssRules` and `rulesFor(el, css)` (the rules that style an element, `@media` included); a line `diff` and `diffHtml`; `showExample({ title, html, css, notes, snippet, onInsert })` (Example Code ↔ Example Website with tap-a-line highlighting, a Try it copy that's never saved, Copy, and **Insert a starter at my cursor**, which says what it adds and asks first); `tagExplorer()` (14 tags: purpose, syntax, a sandboxed mini preview, a common mistake); `GLOSSARY` and `term(word)` (toggletips); `issueList(issues)` (What's wrong, Why it matters, How to fix it, Show me a hint, and a **Find it** on every issue).
- Test: `node tests/tools/test_web_studio.js` (coloring keeps every character, pairs, tidy, explanations, CSS rules, the diff, and the pictures).

## Build Your First Website (the web workshop)
- **Instructor guide:** `missions/coding/build-your-first-website/` (README, `01-instructor-guide.md`, `02-printable-cards.md`; the same template for all three workshops). When a level, stage, budget, or dataset result changes, update the guide's course map and answer guide too.
- Lab `build-your-first-website` (`lab-website.js`, `.ws-` styles), stages in `website-stages.js` (`SE.websiteStages`: `BUSINESSES`, `STAGES`, `BROKEN`, `SHIP`). Library entry `lab-build-your-first-website` (group `web`); template `tpl-ws-first-website` (`reviewed: false`).
- 8 stages in 4 chapters: Plan Your Website, Build the Bones, Tell Your Story, Connect and Illustrate, Give Your Website Style, Build for Everyone, Fix the Broken Website, Ship Your First Website. Stages 2–6 grow one project; stage 7 is a separate broken page (four bugs: a big `<p>` pretending to be a heading, a missing alt, "click here", low contrast); stage 8 starts from a clean starter.
- **Planning Studio and My Website Plan** (`website-plan.js`, `SE.websitePlan`): stage 1 is a studio with five parts (idea cards plus **Surprise me** from curated lists, no AI; name, purpose, audience, what's unique, a goal; headline, opening sentence, three things, a built-in picture, link words; colors with presets, style, mood; sections put in order with Up and Down), each with a **Why?** toggle, a planning mockup labeled as a sketch, and a readiness checklist with teaching messages. Required: a name, a purpose, a headline (2+ words), and an opening sentence (5+ words); the five-second partner test is optional. Plan v2 lives in `state.plan` (`migrate()` turns an old `business` save into a v2 plan for that business, keeping the old notes); `subject(plan)` gives the code stages their words. On stages 2–8, **My plan** opens a panel beside the code (Esc closes it and returns focus); this stage's parts are marked; edits save to the plan and never change code; **Use in my code** buttons say what they'll add and add it on a second press (the headline fills an empty `<h1>` instead of adding one; colors go into the CSS body rule). The plan's name is the `<title>` line in the locked start of the file.
- Students type real HTML and CSS (separate tabs). Helpers only put real code in front of them: the **Tag Shelf** (types a tag pair at the cursor with `insertText`, so the browser's own Undo works), **Find it** (tap the preview to select the code; the tag at the cursor is outlined), **Code Coach** (one line about the tag or property at the cursor), the **Color helper** (pickers that rewrite a value in the CSS text), and Desktop/Phone previews.
- `SE.website.checks(doc, ctx)` reads the rendered page and returns `good`, `fix`, or `person` per check (`h1 p h2 list img alt link style contrast narrow phone own`), plus "Check with a person" items for alt text and link words. Links may jump to an `#id` that exists on the page (or `https://`). Contrast asks 4.5 to 1 for all measurable text. Stage 7 checks in three steps (kinds of problems, then where, then verify); stage 8 also needs the page to fit a phone and the Phone preview to have been used. Any valid page passes; nothing compares against an answer.
- **Privacy:** plans and code stay on the device (`localStorage stem207.website.<studentId>`, or `sessionStorage stem207.website.preview` for an educator previewing). The log gets only check names and stage numbers. Teachers review a page in person ("will show you") or from the printed summary.
- **Screen (studio pass, November 2026):** the brief leads with the goal and Need a hint? (`briefFirst`, wide body). The code boxes use `SE.codeEditor`: colored code, line numbers, and the start of the file (`<!DOCTYPE html>` … `<body>`, with the page's `<title>` and, on CSS stages, `<link rel="stylesheet" href="style.css">`) shown locked and folded into one "Lines 1–N" row (`foldTop`). The tabs read **HTML index.html** and **CSS style.css**. The toolbar has **Show an Example** (always there: `SE.webStudio.showExample` with `EXAMPLES[stage]` from `website-lessons.js`, about a separate demo topic, Maine Moose Facts, so it shows the idea without doing the student's page; **Insert a starter at my cursor** says what it adds and asks first) and the **Tag Explorer**. **What does this do?** (`#ws-coach`) explains the tag, attribute, or CSS at the cursor (`SE.webStudio.explain`). There's no Extra help, Bigger code, or Challenge mode.
- **Lessons: learn first, then try** (`website-lessons.js` `LESSONS[stage]`, drawn by `lessonStepper` in place of the brief's step list on stages 2–8): What we're building · Why it matters · Learn (cards with code, and glossary words as toggletips via `teach()`) · See a working example (opens Show an Example) · Start coding · Try an experiment (predict with buttons, then the explanation, then try it in the code) · Check your understanding (presses Check my page) · Common mistakes · What you just learned (the stage's `learned`). Next and Back, a dot row, and the step is remembered for the session (`stem207.website.lesson.<stage>`). It never blocks the editor. The concepts across the 8 stages: planning; how the web works (HTML/CSS/JS), the parts of a page file, elements, tags, `h1`, `p`; `h2`, lists, nesting, `section` and semantic HTML; attributes, `img`/`src`/`alt`, links/`href`/`id`; CSS rules, selectors, hex colors; contrast and screen readers; debugging; testing like a visitor and finishing.
- **Starter code:** stage 2 starts with `<h1></h1>` and a comment saying where the opening sentence goes; stages 3 and 4 add a comment where the new part goes (only once, only on a page without that part); stage 5 starts an empty `style.css` with a comment. Nothing is replaced.
- **Debug Detective** (stage 7's experiment step): six isolated broken pages, one bug each (a missing `</h1>`, tangled `<li>` nesting, a mistyped `<pp>`, an empty alt, a typo in `src`, skipped heading levels), each in its own editor with a preview, Check my fix, a clue, and an explanation. They never touch the student's page.
- **Milestones** (said once, as a toast, saved in `state.milestones`): the first heading on the page, the first working link, the first bug fixed.
- **Check my page lists every problem:** `checks()` also returns `issues`, one for each independent problem (each picture without good alt text, each bad link, each hard-to-read color pair, each extra `<h1>`), with **What's wrong**, **Why it matters**, **How to fix it**, **Show me a hint** (a pattern, never the whole answer), and its own **Find it**. Find it selects the problem's code and names its line (`goTo`), or, for a missing part, draws a dashed "Add your `<h2>` here" line where it could go (`insertPoint(check, html, css)` → `showInsertPoint`), without changing the code. Issues have stable keys (`alt:<wk>`, `link:<wk>`, `h2`…), so after a re-check every Find it still goes to its own problem. Contrast goes to the color in the CSS; the Phone check focuses the Phone button. `results` still holds one state per check, for gating. Stage 7's first check names the kinds of problem, and the button then reads **Show where they are**.
- **Level Up: Try This Next** (optional, folded under the results): six goals, each with what it practices and what success looks like (two `<h2>` sections, a second jump link, a `<section>` with its own heading, a second picture with alt text, 7 to 1 contrast, fits a phone). They tick when Check my page sees them and never block a stage (`challenges(doc, ctx)`).
- **Screen reader view** (`SE.website.readOut(doc)`: headings, paragraph text, lists and items, pictures by alt or file name, links, in reading order; **Read it to me** uses `SE.speech.read`). Person items for alt text and link words carry a `key` (`alt:…` / `link:…`) and a **Yes, it's clear** / **Change it** answer, saved in `state.confirmed[stage]` by key, so changing the words asks again. A stage with `confirm: true` (stage 6) passes only when every one is confirmed, and opens the view when that's all that's left.
- **Stage 8:** with a project from stages 2–6, it asks **Start from my page** or **Start blank (challenge)** (`state.shipFrom`; the win result records `from`). **Check my page** runs every check; when all pass, **Finish my website** appears (hidden again by any edit), with a note that the website stays on this device and isn't published on the internet. Pressing it finishes the lab.
- Test: `python3 tests/labs/test_website.py` (all 8 stages, alternative answers, the checker and `readOut` on real pages, the stage 6 person checks, the stage 8 start choice and two-step ship, results on the first screen, hostile code with network and dialog watching, drafts, and phone width).

## Python ramp: mini-Python and the Harbor Python Lab
- **`assets/js/labs/minipy.js`** (`SE.minipy`, loaded after `harbor-engine.js`): a small Python subset that compiles to Harbor Code's block programs, so `SE.harbor.run` runs it. No eval, no library.
  - `parse(src, { varName, goal }) → { main, fn, fnName, errors: [{ line, message }] }`. Supported: `move()`, `turn_left()`, `turn_right()`, `haul()`, `set_trap()`, `for i in range(n|steps):`, `while not at_wharf():` (`at_mooring()` with `goal: "mooring"`), `if at_buoy()/at_spot()/ledge_ahead()/ledge_left()/ledge_right():` (the ledge checks have `else`), `steps = n` / `+=` / `-=` (another name with `varName`), one `def name():`, `pass`, and comments. Tabs count as 4 spaces.
  - Errors are for students: they name the line and say what to try (a missing colon, indenting, an unknown name with a "did you mean", elif, a second function).
  - `toPython(main, fn, fnName, opts)`: Harbor Code's **See it in Python** (a folded panel under the program). `toPythonLines` gives each line with its block id, for Captain Code's side-by-side view.
- **Harbor Python Lab** (`lab-python.js`, id `harbor-python`, `.py-` styles): 12 levels in 4 chapters (Read it, Put it in order, Fix it, Write it). Level kinds: `read` (marks A/B/C and an `answer`), `parsons` (`lines`, tap to add, Indent/Outdent buttons, no dragging), `fix` (`code`), `write` (`starter`, `maxLines`, `mustUse`). Tab leaves the editor (no keyboard trap); Indent/Outdent buttons do the indenting.
  - Pure rules: `SE.harborPython.check(levelIndex, src)` and `predictEnd(levelIndex)`.
  - Activity `lab-harbor-python` is in Coding Foundations stage 6 and the Python group.
## Crews: AI Engineer (the first workforce track)

## Pattern Machine Lab: Train the Machine (STEM Coliseum AI workshop 1)

- **The model** (`ml-kit.js`, `SE.mlKit`, loaded before the lab): six traits (`color`, `shape`, `eyes`, `horns`, `antennae`, `tail`), all drawn by `creature(traits, size, label)` (`label " "` = decorative, `aria-hidden`). k-nearest neighbors: distance = number of traits that differ; ties go to the example added first; plain majority vote (K = 1, 3, or 5); `agree` = winning votes ÷ neighbors, shown as the "model confidence score", never as a probability. `knn` accepts only `{ id, traits, label }`, so no rule can reach it. `evaluate(train, test, { K, threshold, novelty })` refuses train/test leaks (same id or same traits) and returns accuracy among answered, overall, coverage, `byGroup(trait)`, and `byCombo([traitA, traitB])`. Also `rank` (every example by distance; knn's neighbors are its first K), `confusion(res)`, `trainAccuracy(train)`, and `contradictions(set)`. Bounded at 40 training and 30 test examples. **Advanced option** `features` (a list of traits the distance counts; Researcher mode only): left out or invalid, all six count, and every result is exactly the legacy one (asserted on every dataset). The art groups each part as `<g data-trait="…">` (`"shape color"` for the body), so a lesson can highlight one feature.
- **Pattern Machine 2.0 modules** (loaded in this order after the data: `pm-ui.js` → `pm-explain.js` → `pm-studio.js` → `pm-knowledge.js` → `lab-ai.js`):
